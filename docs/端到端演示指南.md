## 2. 单Agent与多Agent

点击“单Agent问题示例”，再发送。观察实际规划结果、Worker判断、工具、来源、状态和provider记录；问题示例不会在点击时自动调用模型。真实Lead可能因问题解释而选择不同计划，界面显示实际任务，不把提示词角色数当作实际参与数。

点击“多Agent问题示例”，再发送。预期research检索，consultation解释，diagnostic依据research来源检查，Lead汇总。看3个实际任务、角色、依赖、每任务调用与最终状态。诊断角色在这里检查软件规则，不做临床诊断。

若某任务失败，其依赖显示blocked；可用输出可形成partial，不能冒充完整成功。少量引用/任务检查通过不等于医学正确。工具或输出预算不足会显示具体错误；已取得的资料会标为预算受限，不伪装成离线成功。

输入“请澄清我的请求”验证等待补充，填写具体问题后恢复；也可取消等待运行。刷新/重新登录后选择旧会话，再看SQL历史和运行结果，不重复提交。网络结果只是PubMed索引元数据。

## 3. 服务端模拟登记完整链路

同一登录身份与会话下点击“打开服务端模拟登记”。它与咨询主图是不同分支：咨询模型不拥有确认或登记写入工具。

1. 输入“登记3份血液样本”，点击“生成服务端草稿”。显示缺项目、接收日期和存储区域；本人SQL记录仍为0批。
2. 在草稿中选DEMO-A、2026-10-13、DEMO-B区域，保存编辑。草稿升版，字段完整后变为待核对。
3. 点击“核对当前版本”，查看确认对象；此时仍未登记。把数量改为4，确认区立即失效；保存编辑后升为新版本，需再次核对。
4. 再核对新版本，勾选“我已核对…”，点击“明确确认模拟登记”。只有此操作通过服务器身份、字段、版本和凭据校验才写入1批，生成4个SYN编号。
5. 再生成另一份完整草稿，点击“取消服务端草稿”。状态已取消，记录数仍为1；旧确认再提交会被拒绝。
6. 查看登记审计；刷新或重新登录后选择原会话和草稿，SQL状态与记录保留。刷新不会自动确认，未完成确认需要重新核对当前版本。

演示规则：DEMO-A/B项目、组织/血液/唾液、DEMO-B/C区域、数量1–20整数、有效YYYY-MM-DD日期、备注最多300字。自然输入采用有界规则提取，歧义或缺字段保留空值供补充；不声称可理解所有自然语言。备注在表单中编辑。未知项目、无权限、旧版本、未核对或未明确确认均零写入。

## 4. 暂停、重试与持久化

查询使用LangGraph v3检查点；登记使用registration_graph_v1确定性提取/校验，待补充与待确认状态由SQL草稿持久保存。登记确认不依赖进程内变量或查询Worker检查点。

每项登记操作都有独立request_id。响应不明先刷新草稿/记录，或重放同一个request_id和完全相同请求；不会机械创建另一条记录。相同键用于不同操作/内容返回409；记录、草稿终态、幂等回执与审计同事务提交。编辑或取消与确认竞争只有一个有效结果。

浏览器面板在网络失败后保留同操作请求标识，字段编辑清除本地确认凭据。关闭/刷新页面后可以读取SQL草稿，但不会把历史确认自动恢复成用户同意。

左侧“浏览器登记/浏览器记录”是原localStorage演示，不计入SQL批次。重置浏览器演示只影响该浏览器数据，不清除后端SQL；请在后端联调中看“本人服务端模拟记录”。
