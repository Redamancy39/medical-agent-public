# 临床循证医学系统消融与对照实验报告 (规范化评测版)

## 一、 评测规范与环境约束说明
- **底层底座模型**：DeepSeek (统一 `temperature=0.2`, `max_tokens=1000`)；
- **知识库基座**：Milvus BGE 稠密向量库 + BAAI/bge-reranker-v2-m3 本地 GPU 重排；
- **独立评测标准**：采用四维独立评价体系（动作完整性25分、要点与否定语义覆盖35分、安全红线20分、证据存在与支持度20分），不依赖本系统内部 Reviewer 自评；
- **样本集定义**：在 4 例典型高难度开发集题目（急腹症休克、创伤微循环衰竭、指南高血压分级、SPC联合降压）上进行，**正式测试集保持严格冻结**。

## 三、 实测技术发现与客观局限性

1. **Naive RAG 修复生效**：
   - 修复了此前检索结果字典按对象属性访问引发异常、静默退化为零检索的缺陷；
   - 修复后 Naive RAG 检索状态均为 `success`，平均每题实际召回 3 篇文献并成功注入 Context，证据支持分由无检索基线的 5.0 分提升至 10.0+ 分。
2. **多智能体审核系统的真正优势点**：
   - 在证据支持度（Grounding Score）维度，Ours（10.9分）显著高于 Naive RAG，原因在于医学审核器对初稿未证实断言执行了修剪，且提供了字符级 Span 锚定；
   - 在急危重症处置上，Priority Wave DAG 强制生命体征稳定与 120 呼叫置顶，动作规范分维持满分。
3. **样本量与结论边界声明 (严谨性声明)**：
   - 本次实验基于 4 例典型高难度开发集用例，**不得将当前无违规等同于统计学意义上的“100%安全”或“零幻觉”**；
   - 多智能体协作和实时审核带来了额外时延（约 17.6s vs Naive RAG 3.8s），Token 开销也有所增加，这是生产落地必须权衡的工程代价。
