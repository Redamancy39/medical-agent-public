# 医学知识库与问答评测计划

初版日期：2026-10-13；实施更新：2026-10-14。医学问答和面试展示优先，首批成人高血压、2型糖尿病健康知识。登记保留模拟演示，前端后续由用户重新设计。本次完成H1–H3：20份来源、40个医学片段、60题评测草稿；详细证据见[医学资料与知识库验收](医学资料与知识库验收.md)。以下H4/H5质量评测与展示内容仍为计划。

## 1 当前基础与下一阶段目标

查询主链已有JWT、SQL上下文、Mem0、LangGraph单多Worker、Milvus/BGE、本地bge-reranker-v2-m3、PubMed索引与真实状态记录。G最终123项后端回归和3题单多配对验证的是软件流程；该批次3份合成文档继续保留。H另建20份NLM来源的独立医学库，中文为绑定原文的编辑摘述，未经过医学专业复核；不把检索结果或工程成功率称为医学准确率。

下一阶段交付一个范围明确、出处可查的医学问答原型：常见健康知识能基于资料回答，信息不足能追问，资料缺失能说明缺口，引用支持实际结论；面试中能展示RAG与重排的贡献，以及多Agent的收益和代价。先保持DeepSeek Flash、现有BGE和本地reranker，不微调、不为换框架更换模型。

覆盖定义、风险因素、生活方式、监测与检查的一般解释、就医准备和文献适用范围。合成个人场景用于测试追问与安全边界，不作个体确诊、处方或自主调整药量。孕产妇、儿童、急症复杂诊疗和其他专科留到后续；跨范围问题需区分可解释的通用知识、需专业处理的问题和当前库无法支持的结论。

## 2 医学资料选择

先做20–30份小规模资料；一份指独立来源页面或文档，不把一份文件拆出的章节算成多份独立证据。中文优先，英文作为补充，兼顾基础知识、监测、生活方式和就医边界。数量不足时如实列出缺口，不为凑数导入转载、过期或无法确认权限的材料。

| 来源 | 初期用途 | 纳入条件 |
|---|---|---|
| WHO中文实况报道及相关出版物 | 两主题的基础知识、风险因素与公共健康背景 | 保存原文URL和版本；逐页核对使用条件，保留适用人群 |
| 国家卫生健康委等中文官方资料 | 国内健康教育、营养和运动资料候选 | 取得完整正文，确认发布单位、日期及使用条件后才入库 |
| MedlinePlus健康主题Summary与NLM医学检查说明 | 英文知识与监测解释的补充 | 只纳入确认可复用的指定内容；不自动跟随链接抓取第三方百科或药品说明 |
| PMC Open Access Subset论文 | 后续文献解释与证据适用范围示例 | 逐篇许可清楚、主题相关；按研究类型标注，预印本与正式发表分开 |
| 原项目10份TXT | 对照原项目和学习检索结构 | 来源未经核对前不作为医学标准答案或可信知识来源；不修改原文件 |

已找到的候选入口是[WHO高血压](https://www.who.int/zh/news-room/fact-sheets/detail/hypertension)、[WHO糖尿病](https://www.who.int/zh/news-room/fact-sheets/detail/diabetes)、[MedlinePlus高血压](https://medlineplus.gov/highbloodpressure.html)与[2型糖尿病](https://medlineplus.gov/diabetestype2.html)。官方页面的存在不等于本文已完成全部资料准入。

[WHO版权说明](https://www.who.int/about/policies/publishing/copyright)要求按具体材料的许可使用；[MedlinePlus内容说明](https://medlineplus.gov/about/using/usingcontent/)区分可复用的主题摘要和受保护的第三方内容；[PMC说明](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/)明确不同文章的许可不同。资料清单分别记录本地导入、向模型提供片段、面试截图和公开分发的允许范围；不把“公开能看”直接解释为可打包发布。

国内候选入口包括[卫健委2024年慢性病营养和运动指导原则解读](https://www.nhc.gov.cn/ylyjs/gzdt/202407/0b07b1f34bc94bbfaf5ecf114762d479.shtml)。本次只确定候选入口，正文获取、版本及使用条件在资料批次核对；不会据此先生成临床标准答案。

## 3 资料整理与知识库构建

流程为：来源清单 → 保存允许使用的原文快照 → 提取与人工抽查 → 保留结构分块 → BGE向量化 → 独立Milvus库 → 候选召回 → 本地重排 → 带出处的片段供模型回答。

| 要保留的信息 | 作用 |
|---|---|
| 文档ID、内容hash、版本、抓取时间、原始URL | 追溯同一来源与复现知识库快照 |
| 发布单位、发布日期、章节或页码、原文位置 | 用户能回到支持结论的具体段落 |
| 主题、语言、国家或地区、适用人群、资料类型 | 区分指南、科普、研究和不同适用范围 |
| 许可及允许的使用范围 | 决定是否可导入、发给模型或随面试材料分发 |
| 出处核对状态、内容复核状态、有效或被替代状态 | 出处真实与医学内容已专业核验分开记录 |

重要数值、单位、否定词、条件、表格列名和脚注一起保留；不能把结论与适用条件切到无法关联的两块。先按标题和段落分块，以约500–900中文字符为开发集试验范围，与现有700字符/100重叠基线比较。英文记录实际token长度；超长表格或上下文单独处理。

当前工具Source正文上限1000字符、reranker输入上限512token；医学资料整理必须同时检查这两个限制。需要更多背景时按来源定位取父段落，但不能把超长原文直接塞回现有契约，导致裁掉条件或整轮失败。

中英文版本、转载和同机构同内容按来源家族去重，不能当成独立交叉证据。同主题不同地区或版本的建议保留各自适用范围；不简单多数投票，也不按“日期新”覆盖所有地区的材料。标记被替代版本，不混为一条无条件结论。

医学库拟使用独立knowledge_medical_v1目录或集合，和软件合成库分开；构建清单记录文档及片段的真实数量。保留现有库作为软件回归基线，切换配置可回退。不打开原项目参考数据库，不重新下载用户已有reranker。

现有Source.verified固定为false，不能因“官方网页”就改成临床验证通过。后续分别展示出处核对、资料版本与医学复核状态，避免把程序校验或重排分数当成可信度概率。

## 4 医学评测集

先构建60题，其中20题开发集、40题冻结测试集。高血压和2型糖尿病在可支持的类别中尽量均衡；来源不足的题不硬写答案，调整范围并记录原因。

| 类别 | 总题数 | 开发和冻结测试 | 验证重点 |
|---|---:|---:|---|
| 基础知识与单来源解释 | 20 | 6和14 | 查到正确段落并准确解释 |
| 合成场景与信息不足 | 10 | 4和6 | 追问条件，不把一次描述当成确诊 |
| 多来源比较与适用范围 | 10 | 4和6 | 区分地区、版本、人群与证据限制 |
| 库外问题与缺证据 | 10 | 3和7 | 正确说明未知，避免凭空补出处；也不能拒绝所有可回答问题 |
| 风险信号与不当请求 | 10 | 3和7 | 高风险请求的及时就医导向、用药边界与资料注入防护 |
| 合计 | 60 | 20和40 | 分类别报告，不混成一个模糊准确率 |

每题记录问题、主题、需要回答/追问/说明未知的预期动作、参考要点、禁止结论、原文支持位置、适用版本、可接受同义表达、核对者及复核状态。金标准优先依据允许使用的来源逐条核对；模型生成的参考答案只作草稿。

同一问题的改写、同一合成场景的变体作为一个题目家族划分，避免开发集和测试集泄漏。测试问题、参考答案与评分说明不进知识库，也不进入Lead/Worker提示。相关医学原文可以在库中，评测按开放资料RAG任务定义；不把查到原文事实当成作弊，也不把公开题集当作模型从未见过的数据。

首批可设计的问题类型例如：收缩压和舒张压的含义；2型糖尿病可能没有明显症状时该如何理解筛查；一次测量能否直接得出诊断；两份材料的判定标准为何不同；缺年龄、测量条件时应补充什么信息。此处只定义题型，不提前给未经核对的医学答案或剂量建议。

有医学背景的人员可对金标准和争议项作专业复核。没有专业复核时，报告只称“依据出处核对的健康知识与工程评测”，临床有效性仍不作结论。争议或无可靠金标准的题单列待复核，不计入已验证正确数。

## 5 分层评分

先定位“没查到”还是“查到了却答错”，再调整知识库或Agent。关键词评分保留为辅助调试，不能作为最终医学得分。

| 层次 | 指标和评分方式 |
|---|---|
| 检索 | Hit@5：可回答题中，前5个片段至少命中一个原文金标准支持位置的比例；多证据题另报必须支持点覆盖率；MRR记录第一个相关片段的位置 |
| 重排 | 同一批向量候选比较重排前后前5结果、相关位置及CPU耗时；不把候选池不同带来的变化算作重排收益 |
| 回答 | 按金标准要点计完整覆盖、部分覆盖、矛盾或遗漏；检查数值、单位、条件、适用人群和专业术语 |
| 引用 | 拆出需要证据的事实性结论，核对引用是否存在、能否定位、是否真正支持结论；分别报已引用结论支持率和应引用结论覆盖率 |
| 风险与边界 | 预期追问、说明未知或就医导向是否正确；记录个体确诊/调药等越界结论、严重错误和过度拒答，不能用平均分遮住严重错误 |
| Agent工程 | 实际路由与任务依赖、completed/partial/failed、工具错误、截断、模型及工具尝试、实际HTTP/token、端到端P50/P95 |

检索金标准用文档和原文支持位置映射到不同分块配置，不能仅靠“同文档ID”算命中。每项比例公布有效题目数；失败、超时、不完整运行保留在工程分母中。质量项需单列失败回答和待复核题，不能只给完成样本的分数。

答案评分可用独立LLM评审提出逐项证据与分歧，但不得由同一个回答自报正确率。初次冻结测试的可评分回答全部核对出处；模型评审与人工/专业复核的结果分别记录，严重错误和争议题逐项复查。

RAGAS等评估工具后续按需要封装；先把来源支持、金标准和分母讲清楚，避免多装一个框架就声称有了医学质量验证。

## 6 实验配置与公平比较

2026-10-14按用户决定：**默认业务流程和正式医学评测由真实Lead自动选择任务**，单个Worker或多个任务由问题和上下文决定，记录实际计划、选择理由、依赖与参与数。评测只传问题，不传金标准或强制拓扑。下表A/B/C/D保留为后续可选消融思路，本批不强制四套配置，不用固定拓扑替代Lead决策。

| 配置 | 要回答的问题 |
|---|---|
| A DeepSeek直接回答 | 不提供资料时的模型基线如何 |
| B 单Agent与向量检索 | 增加资料后哪些题获得改善或发生错误 |
| C 单Agent与向量检索和重排 | 选片段更准确是否改善答案、代价多少 |
| D 多Agent与相同检索重排 | 对确有比较/依赖需求的题，分工与检查是否带来额外收益 |

知识库、数据集、模型标识/模式、提示版本、输出上限、采样参数、运行顺序和CPU设备固定并记录；温度在API支持时显式配置，不依赖未知默认值。B/C采用相同候选池；可先用当前最多12个候选、前5返回作为基线，扩候选或BM25混合检索另做实验。

C/D使用相同全轮预算、来源、空会话和工具范围，多Agent规划、补查与汇总都计入实际成本。每个配置建立独立会话，不继承另一配置的答案。首轮关闭Mem0写入与实时联网，防止题目变成记忆、资料随网络变化；会话纠正与记忆安全另用合成测试。

只有明确开展执行策略消融时才固定同题拓扑，结果单列；正常运行与本批开发链路始终使用真实Lead。后续评估是否应追问、直接回答或拆任务，不能把固定计划的结果当作路由准确率。Reviewer主要核对引用支持、适用范围和关键遗漏，不做三角色多数投票；明显风险请求先处理就医边界，不等待三角色辩论。

医学知识结论应默认走证据要求，即使问题只需单Worker，也不能因跳过Lead规划就绕过来源检查；追问、说明未知和就医导向不强求伪造引用。三角色职责拟限定为consultation解释问题、research查找证据、diagnostic检查适用范围与推断边界，角色名不表示已具备临床诊断资格。

当前Worker正文通常220字、汇总280字、输出768token是软件演示配置；开发集需专门检查医学条件和必要要点是否被压掉。先减少重复资料与来源编号，再验证裁剪或分段策略；如需提高输出预算，作为明确的独立配置对比记录，不能悄悄扩大某一组的预算。

首轮用4–6道开发题排查链路和评分格式；真实请求每批先设最多40次DS硬上限，不自动重试写入或放大额度。额度用完时余下单元记录not_run。用小样本的实际调用与token估算40题多配置的规模，再分批安排；计费单价和金额若要展示，在执行当日核对，不沿用旧价格。

初次全量结果后，在预先选定的10道代表题上做3次重复观察，检查随机波动；报告仅对这10题的重复稳定性负责。不因某轮结果好就删掉失败轮，不在看过冻结测试后继续调提示并仍称原测试是未见过的测试。

## 7 公共医学基准的补充位置

自建60题优先验证当前知识库和开放式引用回答。[CMB](https://github.com/FreedomIntelligence/CMB)含医学考试与临床问答，后续可按主题和许可选小规模考试题，记录官方题号/版本与单选多选评分；这测的是知识题作答能力，不能替代开放问答的引用支持度。

[PubMedQA](https://pubmedqa.github.io/)是依据摘要回答yes/no/maybe的研究问答任务，留给后续文献解释扩展。使用给定context时不提供long_answer或最终标签，不把它混成中文慢病健康问答准确率。公开基准代码许可与材料本身的使用范围分别核对；本次不下载或批量运行它们。

现有PubMed工具仅返回标题、日期和链接，不支持宣称读过摘要或全文。本阶段本地健康知识问答优先；以后获取摘要/PMC全文时再增加正文类型、许可、段落定位、联网预算和失败状态。

## 8 实施批次与交付

| 批次 | 工作与交付 | 完成标准 |
|---|---|---|
| H1 资料与题目规范 | 两主题来源清单、资料准入、章节覆盖表；先写10道带原文支持的参考问答 | 每份来源/版本/允许使用范围清楚；每题有出处和预期动作 |
| H2 医学小库 | 原文清洗、结构分块、独立导入、位置引用和检索开发报告 | 数量真实，重复导入幂等；关键单位/条件保留；既有库可回退 |
| H3 冻结评测集 | 补齐60题、20开发/40测试划分、题目家族去重、评分说明 | 冻结版本/hash；无答案注入；争议项和复核状态明确 |
| H4 回答与评测 | 引用支持检查、边界处理、真实Lead自动路由，小规模后再分批问答评测；消融按需另做 | 成功失败均计数；有质量、引用、风险、成本及延迟报告；没有预设准确率 |
| H5 面试展示 | 医学问答入口、证据段落、资料版本、演示脚本、架构图和可复现报告 | 能讲清资料→召回→重排→回答→核查；解释为什么并非所有题都用多Agent |

H1–H3的当前交付已完成；测试集冻结后只用开发集调整参数。中文官方资料的正文、版本及使用条件尚未完成准入，继续作为缺口。下一步H4重点核对答案和引用支持，当前检索检查不替代专业医学复核。暂不扩展登记、微调、模型下载或生产部署。

## 9 面试展示内容

准备约5分钟演示：一个单来源问题展示来源定位；一个多来源问题展示实际任务依赖与适用范围；一个缺信息的问题展示追问；一个库外或风险请求展示有边界的反馈；最后展示同题实验的质量与成本。登记仅作为已有模拟业务能力的补充，不占医学问答主线。

面试材料分别呈现三种事实：工程回归是否通过、医学知识要点与引用评测怎样、是否完成专业临床核验。项目介绍使用真实知识库数量、真实测试分母和真实成本；不沿用原手册指标，不把角色数量说成医学能力提升。
